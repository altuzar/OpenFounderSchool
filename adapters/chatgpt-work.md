# ChatGPT Work

Sources: [getting started with Work](https://learn.chatgpt.com/docs/get-started-with-work) and [projects and chats](https://learn.chatgpt.com/docs/projects). Work can use context and create deliverables; local file access depends on the interface and available permissions.

## Project with attached files

1. An adult checks access and terms. Create a private OpenFounderSchool project.
2. Unzip `release/openfounderschool-chatgpt-work.zip` and place COACH.md in project instructions when available; otherwise include it explicitly in the first message.
3. Add STARTER.md as a source with the current lesson and a sanitized checkpoint. A ChatGPT project does not gain folder access just because you paste a path.
4. Open a Work chat inside the project and run the shared acceptance check. Attach missing files; do not accept invented contents.
5. Request one deliverable per session and save the final checkpoint. Check what was persisted and where.

## Desktop with an authorized local folder

If your account and interface allow local access, open the repository folder or a dedicated copy and limit scope. Ask it to read AGENTS.md, COACH.md, and the current week. Repository text does not grant system permissions or guarantee automatic instruction discovery in every Work mode.

## Minimal setup

No plugins, connectors, API key, schedules, or automation are required. Keep reviews manual if the agent proposes routines. Without file access, paste STARTER.md and request text output. Do not assume a new chat knows the previous chat's latest state: load the checkpoint.

We have not configured or run this adaptation in an actual account. Included tests validate kits and content, not feature availability, model performance, or the provider's plan.
