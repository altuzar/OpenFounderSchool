# Budget and operation at rest

Tuition is US$0. That does not make external tools free. Use paper and local materials, or an assistant you already have and are eligible to use. You do not need a VPS, database, domain, API, ads, or payment processor to learn.

## What runs

| Mode | With zero users | Frequency | Deployments | Estimate |
| --- | --- | --- | --- | --- |
| Local files | Nothing | Only when opened or commands run | None | 0 AI calls/day and /month; 0 DB writes |
| Conversational coach | Nothing generated by this repo | Manual requests only | One provider per family | Depends on messages and plan |
| Python tools | Local reads/writes | One execution per command | Local computer | No API or DB; local CPU and disk |
| GitHub CI | No scheduled work | Push or pull request | GitHub Actions | Minutes depend on changes; no cron |
| Possible future routines | Outside this edition | Must be quantified before enabling | Document per family | Not estimated or enabled |

Third-party services may maintain sessions, machines, or subscriptions while this repository is inactive. Close remote tasks and check their dashboards to stop costs. Pausing the curriculum does not cancel provider subscriptions.

## Active-use estimate — projection

Planning assumption, not measurement: four sessions/week × 12 turns/session × 4.33 weeks/month ≈ 208 turns/month per student. At 4,000 input and 1,000 output tokens per turn, that would be about 832,000 input and 208,000 output tokens. Tools, large context, retries, and additional agents can multiply this. Subscription-plan tokens do not translate directly into API charges.

For API use: approximate cost = input millions × input rate + output millions × output rate + tools/hosting. Check current prices directly with your chosen provider. This guide fixes no prices or limits that could expire. Do not use a figure in an older video as a current quote.

## Family budget

Begin with US$0 in additional spending; use existing materials, libraries, and tools. Before a paid experiment, set per-experiment and monthly limits, who pays, and how to stop it. Do not enable automatic top-ups by default. Record AI, storage, payment, and refund costs even when small.

Do not create fake traffic with actual backend writes to make a demo look active. Prefer local fixtures. One write can trigger reads by other subscriptions: count downstream work, not just the initial operation. Disconnect unused views and subscriptions if you later build an app.

Consumed API calls, I/O, and compute generally cannot be recovered by deleting data or reverting code. Storage and cumulative usage are different. Refunds or resets depend on provider policy and must be checked with that provider.
